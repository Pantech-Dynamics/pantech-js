# Contributing to pantech-js

Thanks for helping improve the TypeScript and JavaScript SDK for the Pantech Dynamics public API.
Bug reports, fixes and improvements are all welcome. Please read the
[Code of Conduct](CODE_OF_CONDUCT.md) first, and report security issues privately as described in
[SECURITY.md](SECURITY.md), never in a public issue.

## Development setup

You need Node.js 18 or newer (22 is used in CI).

```sh
git clone https://github.com/Pantech-Dynamics/pantech-js
cd pantech-js
npm ci
```

## Checks

Run these before opening a pull request; CI runs the same ones.

```sh
npm run typecheck
npm run lint          # npm run format fixes what it can
npm test
npm run build
node test/smoke.mjs   # after a build; CI also runs it under Bun and Deno
```

## Layout

```
spec/public-api.yaml   vendored copy of the public API spec (npm run spec:sync)
src/types.gen.ts       generated by openapi-typescript (npm run generate); never edit
src/models.gen.ts      one alias per schema (npm run generate); never edit
src/models.ts          hand-written refinements of generated models
src/types.ts           BodyOf / ResponseOf / QueryOf helpers read from the spec
src/client.ts          Pantech: auth, Idempotency-Key, timeouts, retries
src/errors.ts          PantechError and subclasses; problem+json mapping
src/resources/*.ts     one file per API family
test/coverage.test.ts  every operationId in the spec maps to an SDK method
```

## Keeping in step with the API spec

The SDK is generated from the published OpenAPI spec at
<https://docs.pantechdynamics.com/openapi/public-api.yaml>. A weekly workflow opens an issue when
it changes.

```sh
npm run spec:sync                         # the published spec
npm run spec:sync -- path/or/url.yaml     # or another copy
npm run generate
npm test
```

Add a method for any new operation, add it to the table in `test/coverage.test.ts`, and commit
the generated files. An operation the SDK deliberately leaves out goes in
`scripts/not-in-sdk.json` instead, with the reason; `npm run generate` then leaves out its types.

## Guidelines

- Fields stay snake_case exactly as the API sends them; methods are camelCase. Method signatures
  use `BodyOf<"operationId">` and `ResponseOf<"operationId">`, not hand-written shapes.
- Every request goes through `Pantech.request`, which sends the Idempotency-Key and retries with
  the same one. A write the API does not replay passes `{ noRetry: true }`.
- No runtime dependencies and no `node:` imports in `src/`, so the package runs on Node.js, Bun,
  Deno and edge runtimes.
- Never log or print the API key, and never put it in a URL or an error.
- Add tests for every change in behaviour.
- A change users will notice gets a line under `## Unreleased` in `CHANGELOG.md`, in the same pull
  request.

## Releasing

Maintainers release by renaming `## Unreleased` in `CHANGELOG.md` to `## X.Y.Z (YYYY-MM-DD)` and
bumping the version in `package.json` and `src/version.ts` to match. On push to `main`, the
auto-release workflow tags `vX.Y.Z` if it is new, publishes the package to npm with provenance and
creates a GitHub release whose notes are that section.
